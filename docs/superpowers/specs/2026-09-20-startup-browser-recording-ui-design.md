# 启动、浏览器、录制配置与按钮改造设计

## 目标

本次改造聚焦四个可观察结果：

1. 应用在用户登录 Windows 后尽早启动，不再受注册表 `Run` 启动延迟的主要影响。
2. 自动认证默认在后台无头运行，仅在需要人工处理时打开可见 Edge；录制仍使用可见 Edge。
3. 认证流程页支持安全地导入和导出录制配置。
4. 全局按钮采用一致、紧凑的图标体系，重点改善顶部“关于”按钮和录制页工具栏。

## 非目标

- 不保证应用绝对早于所有第三方程序启动；Windows 不提供可靠的全局启动顺序保证。
- 不导入或导出账号、密码、SSID、认证地址、重试参数等非录制数据。
- 不更换现有 WinUI 3、MVVM、Playwright 或托盘实现。
- 不重做页面信息架构或增加新的认证提供商机制。

## 1. 开机启动

### 方案

用统一的 `StartupTaskManager` 替代 `RegistryStartupManager`。首选通过 Windows 任务计划程序注册当前用户登录触发任务：

- 触发条件：当前用户登录。
- 启动参数：`--background`。
- 延迟：无显式延迟。
- 权限：当前用户、非提升权限，不弹出 UAC。
- 实例：应用现有单实例机制继续防止重复进程。

安装器、设置页开关和卸载流程必须调用相同的启动注册逻辑，避免三处行为漂移。

### 兼容与回退

- 成功注册计划任务后删除旧的 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 项。
- 注册计划任务失败时写入日志，并回退到现有注册表 `Run` 启动项。
- 关闭开机启动或卸载时同时删除计划任务和旧注册表项。
- 升级安装必须清理旧注册表项，避免计划任务和 `Run` 同时启动。

## 2. 浏览器自动化可见性

### 会话模式

`EdgeSessionFactory` 接收明确的会话模式，而不是由调用方传递含义不清晰的布尔值：

- `Recording`：可见浏览器，用于用户录制。
- `BackgroundAuthentication`：Headless 浏览器，用于日常自动认证。
- `InteractiveRecovery`：可见浏览器，用于需要人工处理的恢复流程。

录制器始终请求 `Recording`。认证执行器首先请求 `BackgroundAuthentication`。

### 可见恢复

以下情况触发人工恢复：

- 检测到验证码、短信验证、用户协议或其他外部操作。
- 已录制页面无法出现。
- 已录制元素不存在或不唯一。
- 门户页面在无头模式下无法完成认证，且重试不能解决。

恢复顺序：

1. 保存故障原因和需要打开的页面地址。
2. 关闭无头会话，释放持久化 Edge Profile 锁。
3. 使用同一 Profile 创建 `InteractiveRecovery` 会话。
4. 导航到认证入口或故障页面。
5. 更新应用状态并发送桌面通知。
6. 保留可见会话供用户处理；后台监控继续检测联网结果。

普通网络超时和短暂连接失败不立即弹出浏览器，继续遵循已有重试策略。恢复窗口启动失败时只记录错误并发送通知，不停止后台监控。

## 3. 录制配置导入与导出

### 文件模型

导出文件使用版本化 JSON 包装模型：

```json
{
  "format": "SchoolNetAutoAuth.Recording",
  "version": 1,
  "exportedAtUtc": "2026-09-20T00:00:00Z",
  "recordedSequence": {}
}
```

文件仅包含 `RecordedClickSequence` 及其页面、定位器、步骤和录制时间信息。

### 导出流程

- 录制页提供“导出配置”命令。
- 没有录制配置时命令不可用。
- 使用 WinUI 3 `FileSavePicker`，默认扩展名为 `.json`。
- 用户取消文件选择时静默结束。
- 写入失败时显示明确错误，现有配置不受影响。

### 导入流程

- 使用 WinUI 3 `FileOpenPicker` 选择 `.json` 文件。
- 先读取到临时模型，再验证格式标识、版本、凭据定位器、URL、步骤顺序和定位器字段。
- 未知版本、损坏 JSON 或字段不完整时拒绝导入。
- 当前已有录制时，保存前要求用户确认覆盖。
- 校验和确认全部完成后，才更新设置存储并刷新录制步骤列表。
- 导入失败时保证原录制配置不变。

文件选择器相关的窗口句柄初始化由独立服务负责，ViewModel 不直接依赖 WinUI 窗口实现。

## 4. 按钮与图标设计

### 图标来源

使用 `better-icons` 从 Lucide 集合获取并落地所需图标资源：

- 开始：`play`
- 结束：`square`
- 删除步骤：`trash-2`
- 清除录制：`eraser`
- 重新录制：`rotate-ccw`
- 导入：`file-input`
- 导出：`file-output`
- 关于：`info`

图标作为项目内资源随应用发布，不依赖运行时网络访问。

### 按钮体系

`App.xaml` 将按钮收敛为四类：

- 主按钮：高优先级操作，图标加文本。
- 普通按钮：中性背景、细边框，图标加文本。
- 危险按钮：默认视觉克制，悬停和确认流程强化危险语义。
- 紧凑图标按钮：固定约 `32 x 32`，用于“关于”等工具操作。

通用文本按钮高度约 `36px`，图标约 `16px`。录制页工具栏使用可换行布局，在窄窗口下不压缩文字或造成重叠。顶部“关于”改成透明背景的纯图标按钮，并保留 Tooltip 和键盘焦点状态。

现有混用的 `SymbolIcon`、`FontIcon` 和颜色过重的成功/警告按钮样式将被替换为统一资源。

## 5. 组件与职责

- `StartupTaskManager`：注册、禁用、清理和回退开机启动。
- `EdgeSessionFactory`：根据会话模式构建 Edge 上下文。
- `PlaywrightAuthenticationRunner`：执行无头认证并产出恢复请求。
- 可见恢复协调服务：关闭无头会话、打开可见会话并维护其生命周期。
- 录制配置序列化器：导入、导出及版本验证，不依赖 UI。
- 文件选择服务：封装 WinUI Picker 和窗口句柄初始化。
- `RecordingViewModel`：暴露导入、导出命令及命令可用状态。
- XAML 资源：统一按钮样式和本地图标资源。

## 6. 错误处理与日志

- 计划任务注册失败、注册表回退结果和启动项清理均记录日志。
- 无头认证失败应区分可重试错误和需要人工处理的错误。
- 可见恢复失败不会覆盖原始认证错误。
- 导入错误必须包含用户可理解的原因，但不显示敏感配置内容。
- 应用退出时释放无头、录制和可见恢复会话，避免 Edge Profile 锁定。

## 7. 验证与测试

自动测试覆盖：

- 计划任务参数生成、旧启动项清理和失败回退。
- 录制、后台认证和人工恢复三种会话模式。
- 只有需要人工介入的结果才触发可见恢复。
- 录制配置导出再导入后的等价性。
- 格式错误、未知版本、损坏 JSON 不覆盖原配置。
- 导出文件不包含账号、密码和其他应用设置。
- `RecordingViewModel` 导入、导出命令状态和覆盖确认。
- 新增 XAML 与图标资源可加载。

完成前执行：

1. 完整测试套件。
2. Release 构建。
3. 发布脚本。
4. 手动验证登录启动、后台认证、人工恢复、Picker 交互和窄窗口按钮布局。
